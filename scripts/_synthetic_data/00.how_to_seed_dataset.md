## Seed Dataset — What's inside

> Use this dataset if you're skipping Phase 4 (synthetic data generation). Load it and go straight to Phase 5 (coding).

### The graph at a glance

```
(:Aircraft) <-[:FOR]- (:WorkOrder) <-[:PART_OF]- (:Operation) -[:PRECEDES]-> (:Operation)
```

Three node types, three relationship types. That's the entire model.

### What was generated

| Element | Count | Details |
|---------|-------|---------|
| Aircraft | 3 | AF-001 (Narrow-Body, delivery May 15), AF-002 (Wide-Body, June 15), AF-003 (Regional, July 15) |
| Work Orders | 12 | 4 per aircraft, mix of Started and New |
| Operations | 170 | 10-18 per work order, named after real aerostructure tasks |
| PRECEDES (intra-WO) | 333 | Dependencies within a single work order — non-linear DAG with branches and convergence |
| PRECEDES (cross-WO) | 22 | Dependencies across work orders on the same aircraft — **this is what makes CPA possible and what SAP can't do** |

### Key design choices

**Durations**: every operation has an `estimatedDuration` in hours, ranging from 4h (half day) to 48h (6 days) in 4h steps. This is the weight for the critical path calculation.

**Explicit vs default sequencing**: ~55% of PRECEDES relationships are `type: "explicit"` (properly maintained in SAP), ~45% are `type: "default"` (assumed sequential due to poor data quality). This mirrors Thomas's comment in the brief: *"only about 60% are properly maintained."*

**Intentional bottleneck**: OP-0042 ("Autoclave Curing (Critical)") has a duration of 72h and sits on the critical path of AF-001 — the aircraft with the tightest delivery date. It has predecessors from two different work orders (including one cross-WO dependency). This is your what-if demo target: *"if OP-0042 slips by 3 days, what happens to the AF-001 delivery?"*

**No scheduled dates on operations**: only durations and dependencies. The schedule (start/end dates for the Gantt chart) is what your CPA computes — it's the output, not the input.

### How to load

Open your AuraDB instance in the Neo4j Console, go to the **Query** tab, paste the content of `seed-dataset.cypher`, and run it.

Alternatively, via MCP in Cursor:
> *"Load and execute the content of seed-dataset.cypher on my Neo4j instance."*

### How it was generated

The dataset was generated by `generate_seed_dataset.py` — a deterministic Python script (seed 42, zero dependencies). You don't need to run it; the Cypher file is the deliverable. But if you want to understand or modify the generation logic, the script is there.
